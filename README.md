# 自研智能排产系统 (APS MVP)

基于 Google OR-Tools (CP-SAT) 运筹优化求解器的双阶段自动排产引擎（MVP 版本）。

## 1. 项目背景与目标

本项目针对流程/离散制造企业的排产痛点，旨在将物流排产专家的经验规则算法化、工程化：
* **聚焦范围**：单一代表性产品家族（雨刮传动杆总成 `PGLINKAGE` + 自制半成品 `轴套6` 产线）。
* **核心哲学**：不追求纯数学全局最优解，100% 接受次优解；以**准时交付第一**为最高优先级，兼顾产线高利用率与连续紧凑排产。
* **物理约束**：
  * **净需求排产**：`需要生产数量 = 客户需求 - 可用期初库存 + 安全库存(Target Stock)`，库存已覆盖的需求行不生成生产任务。
  * **上下工序按班次累计齐套**：`x` 班次的半成品产出（含库存已覆盖部分）可供 `x+1` 班次装配，两阶段按件流水搭接，不再是"半成品全部完工后成品才能开工"。
  * **MPQ 分级取整**：成品总量与各班次产出严格按 MPQ 整倍数排产（如 48、96、192）；半成品不取整倍数，只要求产量为整数件且不低于 MPQ 最小投产批量（如 48、50、60 均可）。
  * **Option B 三班制**：早班 (07:00~15:00)、中班 (15:00~23:00)、晚班 (23:00~07:00)，班次即模型的最小时间原子。
  * **班次产能利用率 ≥ 95%**（WE34 第一优先级）：按"产线 × 班次"聚合口径校验，每条产线允许最后一个收线班次不足 95%。
  * **单班最小投产批量**：一个班次只要开工某型号，当班产出就不低于该型号的最小投产批量（成品一个 MPQ 批次，半成品 `MPQ` 件）；否则目标函数会把型号摊成每班几件的碎片，产线无法执行。
  * **换型集中**：换型按"型号连续生产块"计数并计价，块数最少即换型次数最少；同一条产线上优先把一个型号跑完再切下一个。
  * **毫秒整数时间标度**：单件工时 `CT / TRP` 是非整数秒（如 27/0.85 ≈ 31.76s），CP-SAT 只接受整数系数，模型内部统一以毫秒计时长、以"件"计半成品产量。

```text
APS_MVP/
├── APS Database- Simulation draft.xlsx  # 主数据与排产输入/输出表格 (共14张Sheet，含39条原则、模具、PM维保、物料ETA及客户分级)
├── requirements.txt                     # Python 依赖项 (openpyxl, ortools, fastapi, uvicorn)

├── Specification/                       # 业务功能规格与调研文档
│   ├── aps_project_progress.md          # 项目研发进度与里程碑台账 (M1..M9 收官全记录)
│   ├── aps_rules_registry.md            # 39条排产规则全景台账、规范化解析与五大架构共识
│   ├── aps_functional_spec.md           # 功能规格设计说明书 (v0.5 全要素规则演进版)
│   ├── aps_ipo_overview.md              # Input - Process - Output 概览与组织层级架构
│   └── aps_checkList.md                 # 物流专家访谈提纲
└── src/                                 # 排产系统源代码
    ├── rules.py                         # 39条全要素业务规则注册表 (9大业务分类 + 5级性质)
    ├── data_loader.py                   # 读取 Excel 参数、BOM、需求，并解析模具/PM/物料ETA/客户评级主数据
    ├── shift_manager.py                 # LineCalendar解耦日历与三阶排班模式 (做四休三/做五休二/连产)
    ├── prechecker.py                    # 排产前粗能力宏观可行性预检与《交期调整建议表》
    ├── scheduler.py                     # Google OR-Tools CP-SAT 班次槽位优化模型 (顺位前拉/模具独占/维保避让/客户分级保供)
```

## 3. 环境准备与运行

### 安装依赖
```bash
pip install -r requirements.txt
```

### 一键启动可视化 Web 演示系统 (本地 UI)
```bash
python run_web.py
```
启动后在浏览器打开：**`http://127.0.0.1:8000`** 或 **`http://localhost:8000`**

Web 界面主要特性：
- **① 生产平衡与负荷总览 (参考 `Production Plan Validation.xlsx`)**：
  - 顶部产线负荷概览：按班次展示 `Loading Hours`、`TRP`、`Loading Rate`（利用率 $\ge 95\%$ 达标高亮显示）；
  - 底部物料动态平衡表 (PSI)：按物料展开 4 行（`Customer demand`、`Production plan`、`Stock Balance`、`Coverage days`），支持产成品 (FG) 与半成品 (SFIN) 分页或同屏展示；
- **② 排产工单甘特明细**：查看各阶段工单的起止时间、计划数量、交期达成状态及跨班排布；
- **③ 规则与约束配置 (39 项全要素约束体系)**：
  - 支持 **9 大业务类型**（核心排班、物料与库存、设备与产能、工装与人员、订单与交期等）及 **5 级约束性质** 双维度极速筛选；
  - 列表主视觉突出展示**一句话精炼规则名称**，支持点击一键展开 **Col G 规范化 AI 逻辑代码卡片**（数学公式、业务边界与场景示例）；
  - 支持独立勾选控制，动态联动 CP-SAT 求解引擎与后置独立审计；
- **④ 输入与排产工程主数据工作台 (Tab 4 工业级全新上线)**：
  - 支持在网页中直接维护订单需求数量、交期、期初库存；
  - **模具工装约束看板 (`R-TL-01`)**：展示物理独占套数、换模耗时、冲次设计寿命及累计冲次健康度；
  - **设备预防维护看板 (`R-PM-01`)**：展示 TPM 等级、停机起止班次、停机工时、有效产能清零与跨班处置策略；
  - **关键物料到货看板 (`R-MT-01`)**：展示 PO 采购单号、预计到货班次(ETA)、质检入库工时与放行状态；
  - **客户战略评级看板 (`R-CR-01`)**：展示战略核心客户加权倍率 (10x/3x/1x)、准时交付目标与委外控制策略；
  - 配套实时 KPI 统计卡、模糊即时搜索与在线编辑一键热保存；
- **⑤ 39 条规则合规审计矩阵**：全景查看 39 条规则在当前排产方案下的遵循状态（PASS / FAIL / SKIPPED），支持按业务类别与通过状态快速筛选；
- **执行运算与导出**：一键触发求解（带动态计时与状态反馈），支持点击【导出结果 Excel】下载生成好的排产工作簿。

### 一键执行控制台排产 (CLI)
```bash
python src/main.py
```
流程执行步骤：
1. **前置粗能力宏观预检 (`prechecker.py`)**：核算产线总工时负荷与交期瓶颈，发生绝对超载时抛出 `CAPACITY_OVERLOAD_EXCEPTION` 并生成《交期调整建议表》；
2. **三阶排班日历推荐 (`shift_manager.py`)**：按负荷比自动推荐并绑定日历模式（$\le 4/7$ 做四休三、$\le 5/7$ 做五休二、$> 5/7$ 连续生产）；
3. **CP-SAT 多阶段优化求解 (`scheduler.py`)**：
   - 求解预算 90 秒，深度融入顺位前拉、冻结期时间围栏、模具物理独占、BOM关键物料到货齐套、设备PM维保避让、战略客户保供等全要素约束；
4. **报表与 Excel 回写 (`exporter.py`)**：
   - 自动回写至 `APS Database- Simulation draft.xlsx` 的 **`Production plan-Done`** 表格（分班产量、工时汇总与利用率预警）；
5. **17 项独立硬指标校验与 39 条规则遵循矩阵 (`validator.py`)**：
   - 独立验算 17 项指标（全数达成），并在控制台自动输出 39 条规则遵循全景状态矩阵。

> 口径说明：半成品采用按件排产（单班起投 $\ge$ MPQ），在 95%~100% 区间内精确凑齐；成品按 MPQ 整数倍排产；换型集中打磨将单班并行型号数严格压制在 $\le 3$ 满足 R-FG-13；`准时交付` 在全部运行中保持 100.0%。
