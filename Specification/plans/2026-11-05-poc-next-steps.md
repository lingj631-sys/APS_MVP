## 2. 下一步计划

### P0 — 让「能出解」变稳定（本周）

1. **`changeover` 纳入规则集唯一事实来源**
   - 现状：规则集禁用 `WL_CO` 后，服务端 `price_changeovers` 仍为 True，换模矩阵照旧参与模型；离线（无矩阵）102s 可解，服务端（带矩阵）300s 仍超时。
   - 做法：kernel 的 changeover 判断去掉对 `price_changeovers` 的依赖；规则集声明 `changeover` 时强制旧开关关闭。
   - 验收：温岭 11/01 / 10 天，规则集禁用 WL_CO → 90s 内出解；启用 WL_CO → 结果含换型次数且可解释。

2. **求解预算与超时治理**
   - 默认预算 35s → 90s（服务端下限已有 90s）；超时后自动以 300s 重试一次，并在结果上标注「长预算」。
   - API 返回 `proven_infeasible` / `solver_budget_seconds` / `elapsed_seconds` / `tier_statuses`。
   - 验收：任何超时不再显示为「不可行」；前端有明确标注。

3. **真实数据回归基准**
   - 固定 `current_WL.xlsx` + 参数，脚本跑 3 次取中位数，记录 feasible / 耗时 / 延期数；纳入 CI（标记慢测）。
   - 验收：任一改动导致「从可解变不可解」或「耗时上涨 50%」时 CI 报警。

### P1 — 规则语义与数据前置（下周）

4. **`WL_MPQ_SF` 口径确认**：`unit=piece / min_multiple=100` 是否等价于「每次开工 ≥100 件」；若是，规则集页面应默认勾选「尾单豁免」，并在规则体检里写清楚。
5. **订单提前期字段**：数据侧增加「下单日 / 最早开工日」，让「交期早于生产提前期」在导入阶段被拦截（现在只能排产失败后由诊断发现）。
6. **规则体检扩展**：把「规则条款 vs 数据分布」的可行性预检从 3 条扩到 min_batch / MOQ / 并发窗口 / 模具窗口，尽量在求解前给出结论。

### P2 — 性能与工程化（两周内）

7. **模型瘦身**：任务-班次窗口二分裁剪、hint 强化、换模矩阵稀疏化（只保留实际用到的模具对）。
8. **归因实验一键化**：后台跑 N 次「放宽-收紧」，返回「第一个把结果变无解的规则」表格，替代人工试错。
9. **服务运维**：单进程启动脚本 + 端口占用检测 + `/health` 返回版本号与启动时间（本次已出现僵尸 uvicorn 子进程继续占用 8000 端口并返回旧代码，导致「改了不生效 / 新按钮不出现」）。
