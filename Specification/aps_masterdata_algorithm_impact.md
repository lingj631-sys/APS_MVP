## 1. 结论摘要

1. **数据层已经跟上，算法层大部分跟上。** 新版 15 表把 CT、产线、TRP、目标库存、班次几何迁到更合理的表，后台已完成取源改造；补数后人数、静置时间、模具、产品族、ETA 已有值。
2. **补数后的实际状态（2026-10-31 复核）**：
   - `人数` 已补 FG=3、SF=2；10 天计划 146 个任务 **crew_required=0 的任务为 0 个**。
   - `生产提前期` 不再写回；C4 改为读 `工序提前期-提前准备时间`（45~480min）+ 首批转运批量推导，`lead_time_days=0` 不再等于 C4 失效。
3. **新框架中已经真正生效的增量**：CT/产线从 Routing 派生、TRP/工时/班次从产线基础数据派生、目标库存从库存策略安全库存派生、工作日历四档（做四休三/做五休二/做六休一/做七无休）、班次几何（3×8h / 2×12h）同时驱动日历与求解器。
4. **“已加载但算法未消费”的字段**：`special_shift`、`simultaneous_production`、`product_family`（新列）、`eta_time`、`max_stock`（SF）、`available_qty`（模具套数）。这些字段填了也不会改变排产结果，属于下一阶段算法接线对象。

## 4. 关键影响（按优先级）

### P0：会直接让排产结果“看起来正常、实际缺约束”

**P0-1 人力数据断档（已补模拟值：crew=0 → 0/146）**

- 原因：FG/SFN 的 `人数` 删除后，唯一来源是 Routing『人数』，原表整列为空。
- 现状：已按 FG=3、SF=2 补齐；10 天计划 146 个任务 crew=0 为 0。
- 仍缺：`Line-Staffing` 的班次人数上限、共享人力池；HC-15/SC-10 的“红线/平滑”还没有完整数据。

**P0-2 半成品前置期断档（已改为静置时间 + 首批转运推导）**

- 原因：SFN『生产提前期 (days)』被删除；新框架用『工序提前期-提前准备时间』承载静置时间。
- 现状：`lead_shifts = ceil((静置 + min(工单量,转运批量)×CT/TRP) / 单班分钟)`，C4 软约束读取该值。
- 影响：C4 不再依赖 `lead_time_days`；业务只需维护静置时间与转运批量。

**P0-3 产线基础数据不完整（已补 3 行）**

- 现状：已改为 3 行唯一记录（PGLINKAGE / 轴套6 / 轴套7，8h×3）。
- 影响：班次几何、TRP、容量、日历推荐均按表生效。

### P1：字段已声明，但算法没有接线

**P1-1 同时生产（HC-08）**：FG『同时生产』仅 4 行 Y，但 `ProductionTask` 没有该字段，求解器不会做左右件共模同步产出。
**P1-2 特殊班次（HC-13）**：整列为空，且无消费点；短期可作为“排产提示”，中期需定义班次模板。
**P1-3 产品族（BS-05/SC-10）**：整列为空；Campaign 仍读 `Campaign-Families.csv`，新表族字段未接入。
**P1-4 预计入库时间**：整列为空且未消费；当前齐套只精确到班次。
**P1-5 模具覆盖不足**：37/39 料号有模具（FG 17/17、SF 20/22）；146 个任务中 60 个有模具号，2 个 SF 料号仍缺主数据；“同模连产/换模优化”只覆盖有模具的任务；`可用套数` 仍未参与容量。
**P1-6 MOQ 未生效**：任务已带 MOQ，但 active 规则仍是 `quantity_source=MPQ`；HC-11 只是“数据准备完成”。
**P1-7 目标库存口径变化**：v2 下 FG 目标库存全部来自库存策略安全库存（17/17），旧版为 0；这会改变净需求。需要业务确认“安全库存=目标库存”还是“安全库存=下限”。

### P2：与数据无关的模型缺口（原有路线图）

- C5 独立 Pull、SC-08/SC-09/SC-10；C2-b 已做到主模型 Assign + 小规模同模型 sequence，大规模 sequence 仍回退；
- 连续时间粒度（当前班次粒度 + 班内近似）；
- PM 精确到时刻（当前落到班次）；
- 4 档日历阈值（4/7、5/7、6/7）目前是工程假设，需业务确认。
